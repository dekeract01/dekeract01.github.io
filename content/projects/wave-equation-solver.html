This continuing project uses a one-dimensional linear advection solver to compare numerical implementations across languages, CPU parallelism, distributed-memory computing, and GPUs. The equation is intentionally compact: it makes the full calculation understandable while still exercising grids, boundary conditions, time integration, verification, file output, builds, and performance measurement.

For a periodic sine wave, the analytical solution simply translates without changing shape. Every implementation can therefore be checked against that exact result rather than judged only by its timing.

dphi/dt = -c0 dphi/dx
phi(x, 0) = sin(2pi x)
phi_exact(x, t) = sin(2pi(x - c0 t))

Methods and Implementations

The solver uses fourth-order central differences in space with third-order Runge-Kutta time integration. The benchmark runs on a periodic domain with 2,000,000 grid points, a wave speed of 0.5, a time step of 10-7, and 1,000 iterations.

The repository includes serial C++, Fortran, Julia, Python, Python with Numba, and Rust versions, alongside OpenMP C++, MPI C++, MPI Fortran, OpenCL C++, and CUDA C++ implementations, plus a standard-parallelism Fortran version that offloads plain do concurrent loops to the GPU from a single source. The CPU, CUDA C++, and standard-parallelism versions use double precision; the OpenCL version currently uses single precision.

Results

On the Fedora machine, CUDA C++ is fastest at about 0.767 ms per iteration on the RTX A4000. The result I did not expect was the standard-parallelism Fortran version, which came second at about 1.24 ms on the same GPU. It is ordinary Fortran with do concurrent loops and a single compiler flag, with no CUDA and no directives, so seeing it land within roughly 1.6 times of the hand-written CUDA C++ was a genuine surprise. I am not yet certain where the remaining gap comes from. When I built it, the compiler reported that it was moving the arrays between the CPU and the GPU around each step, so I suspect the difference is mostly data movement rather than the computation itself, but I still need to measure that properly before saying so with any confidence.

The accuracy figure is the reason I keep it beside the timing. An earlier MPI Fortran run sat far from the others, at about 6.17 × 10-7, which turned out to be a halo-exchange bug: I was exchanging only one ghost point when the fourth-order stencil reaches two either side. The timing looked perfectly reasonable, so only the error plot revealed it. After widening the halo to two points, MPI Fortran returned to the double-precision floor near 10-14 along with everything else, including the standard-parallelism version.

On the macOS machine, OpenCL C++ is fastest because its kernels run on the M1 Pro integrated GPU. This one is expected rather than surprising: the OpenCL version uses single precision, so it handles half as much data, and the integrated GPU shares unified memory with the CPU, so there is no separate host-device transfer. The accuracy figure shows the trade-off, with the single-precision error much higher, at around 10-5.

Run It

git clone https://github.com/dekeract01/wavebench.git
cd wavebench/cpp
make run

The repository contains the current code, scripts, benchmark details, and results. The charts describe a particular machine and configuration, rather than universal language rankings.
